# 35-蒸馏小模型成本与效果现状（2026-08）

> 研究日期：2026-08-12（部分检索结果含 2026-08 中旬信息）。
> 研究问题：酒店 AI 公司是否值得把开源大模型蒸馏成 1.5B-8B 行业小模型（调价建议/评价回复/质检等任务），
> 以降低推理成本并在酒店前台无 GPU 普通 PC 上本地运行。当前基线：用 DeepSeek 等 API，实测每店每月推理成本仅 20-60 元。
> 方法：18 次中英文 WebSearch（本环境仅允许搜索引擎，无法抓取原文全文，数据以搜索索引摘要为准）。

---

## 一、概述（一句话判决先行）

**在"每店每月 API 成本 20-60 元"的基线下，蒸馏自有小模型在纯成本上不成立**：
训练的 GPU 费用本身已便宜到可忽略（LoRA 微调 7B 单次仅几十到几百元人民币），
但数据合成、评测迭代、持续跟进基座更新的**人力与维护税**是年化十几万到几十万元人民币量级，
需要约 **300-800 家以上门店**的推理量才能仅在成本上打平——而这还没算轻量档 API 价格可能继续下探。
**唯一站得住的动机是"本地离线运行"**：3-4B 量化模型在 16G 内存无独显办公 PC 上可跑出 10-15 tokens/s，
对短提示、短输出的固定格式任务（评价回复、质检分类）"可用"；但长上下文任务（大段数据的调价分析）
受 CPU prefill 瓶颈制约体验差，且调价建议属于多步推理型任务，恰是小模型最弱的一类。

## 二、关键发现（按五个研究问题）

### Q1. 2026 年蒸馏/微调 1.5B-8B 行业小模型的真实成本

**（a）云 GPU 租价（2026-08 行情）**

- 国际市场：H100 租价 $1.49-$6.98/小时（Vast.ai 最低 $1.49，RunPod $1.99 起，Azure/GCP 最贵）；
  A100 80GB 普遍 $1.09-$2.50/小时。
  来源：https://intuitionlabs.ai/articles/h100-rental-prices-cloud-comparison ；
  https://www.cloudzero.com/blog/h100-gpu-cost/ ；https://www.thundercompute.com/blog/ai-gpu-rental-market-trends
- 中国市场（更便宜）：AutoDL A100 低至 **2.4-3.45 元/小时**（天租 75 元）；RTX 4090 约 **1.2-2.0 元/小时**；
  A100 租价已从 2023-24 年的 15-30 元/小时跌到 3-6 元/小时，供给充足。
  来源：https://www.mornai.cn/news/gpu/mornai-and-autodl-gpu-rent-price-comparison-2026-07/ ；
  https://www.mornai.cn/news/gpu/a100-gpu-rent-trend/ ；https://blog.csdn.net/a123456534/article/details/161020435

**（b）训练本体成本（SFT+DPO，1.5B-8B 模型）——极便宜**

- 2026 年行业共识：**7B 模型 LoRA 微调单次 $5-$200**（io.net 称单卡 <$5-10 可见效；保守估算单张 A100 上
  $40-200/次）；全参微调单次 $40-$1,600。"LoRA 微调的 GPU 费用只要 $3-30，真正的成本在数据和工程"。
  来源：https://io.net/blog/llm-fine-tuning-budget-guide-gpu-costs-timelines-and-what-to-spend ；
  https://www.stratagem-systems.com/blog/lora-fine-tuning-cost-analysis-2026 ；
  https://www.spheron.network/blog/how-to-fine-tune-llm-2026/
- DPO 对齐轮：Mistral-7B DPO 约 48 GPU 时（8×A100）；Qwen2.5-7B 在 4×A100 上 1 万条偏好对约 18 小时
  （≈72 GPU 时）。按国内 A100 3 元/时计，**一轮 DPO ≈ 150-250 元人民币**。
  来源：https://www.spheron.network/blog/dpo-vs-ppo-rlhf-algorithm-production-llm-alignment/ ；
  https://galileo.ai/blog/llm-model-training-cost
- 参照案例：伯克利 Sky-T1-32B 全流程（17K 蒸馏样本 SFT）8×H100 训 19 小时，**总成本 $450**，
  在 MATH500/LiveCodeBench 上打平 o1-preview——32B 尚且如此，1.5B-8B 更低一个量级。
  来源：https://novasky-ai.github.io/posts/sky-t1/ ；
  https://techcrunch.com/2025/01/11/researchers-open-source-sky-t1-a-reasoning-ai-model-that-can-be-trained-for-less-than-450

**（c）数据合成（teacher API 费用）——同样便宜，但依赖迭代次数**

- 典型垂直领域微调数据集的生成预算 **$50-200**（教师模型生成+过滤+LLM 评审）；
  4,000 条合成指令-响应数据成本 <$570（用前沿闭源模型做 teacher 的偏贵情形）。
  来源：https://blog.premai.io/how-to-generate-synthetic-training-data-for-llm-fine-tuning-2026-guide/ ；
  https://arxiv.org/pdf/2408.14774
- 自算参考：若用 DeepSeek 当 teacher（2026-05 价：输出 6 元/百万 tokens），合成 5 万条、平均每条 1K tokens
  输出 ≈ 5,000 万 tokens ≈ **300 元人民币**；即便按 2026-08-17 涨价后峰时 27 元/M 也只约 1,350 元。
  数据合成的 API 费不构成障碍。

**（d）评测与迭代——真正的重头**

- 每个正式评测周期预算 **$500-2,000**（需 500-1,000 条留出集）；加人工评估另加 $2,000-3,000；
  项目至少要按 **3-5 轮迭代**做预算，每轮实验成本≈一次正式训练；失败实验占总预算 20-25%。
  来源：https://arize.com/resources/llm-evaluation-costs/ ；https://aisuperior.com/llm-fine-tuning-cost/
- 全项目口径：数据准备占总成本 40-60%，训练只占 20-30%；企业普遍**把 TCO 低估 3-5 倍**
  （只看训练费，忽略数据、评测、维护）；基础设施管理另加 15-30%。
  来源：https://aisuperior.com/llm-fine-tuning-cost/ ；
  https://blog.eduonix.com/2026/02/hidden-costs-of-fine-tuning-llms-for-production/
- 行业报价区间：小型微调项目 $4K-$150K；带严格评测与部署的 7B-70B 项目 $150K-$750K（含人力）。
  来源：https://sivaro.in/articles/how-much-does-it-cost-to-fine-tune-an-llm-in-2026/ ；
  https://www.techaheadcorp.com/blog/custom-llm-development-cost/

**（e）成本结论（单次 vs 年化）**

- **单次纯算力+API**（数据合成+SFT+DPO+评测推理）：**约 1,000-5,000 元人民币**——不是瓶颈。
- **单次全口径**（含数据工程、3-5 轮迭代、评测集建设、部署联调的人力）：**约 5 万-30 万元人民币**
  （对应海外 $4K-$150K 区间的低-中段，按国内小团队人力折算）。
- **年化维护**（跟进基座每季更新、每 3-6 个月重训、回归评测，见 Q5）：至少 0.5-1 名算法工程师
  （国内年薪 30-60 万元）+ 每年 2-4 次重训的迭代成本 ≈ **年化 15-40 万元人民币量级**。

### Q2. 效果现实：什么任务能接近大模型，什么不能

**可以接近甚至超过大模型的任务型（分类/抽取/固定格式生成）：**

- 微调后的小模型在"定义清晰的窄任务"上稳定胜过通用大模型：工单分类、属性抽取、固定格式生成等。
  Phi-4-mini（3.8B）在结构化抽取基准上打平 GPT-4o；一个 355M 模型在立场分类上 0.94 vs GPT-4 的 0.58。
  来源：https://florinelchis.medium.com/how-companies-actually-use-small-language-models-what-287-case-studies-reveal-d9ea4b61e530 ；
  https://arxiv.org/html/2409.11408v1 ；https://towardsdatascience.com/how-to-choose-between-small-and-frontier-models/
- 定向微调的小模型在**工具调用**（agentic tool calling）上也能超过大模型。
  来源：https://arxiv.org/html/2512.15943v1
- 经验法则："今天的 3-14B 模型在定向任务上相当于 12-18 个月前的 70B"。
  来源：https://www.turingpost.com/p/slmslist

**做不到 / 风险高的任务型（多步推理/长上下文规划）：**

- 2026 公开评测显示：开源小模型与前沿模型的差距在**通用任务上收窄、在复杂推理上仍然显著甚至扩大**——
  最大差距出现在 GPQA Diamond、CodeElo/CodeForces 等推理密集基准；复杂多步推理、规模化的细致指令
  遵循、高级多模态是 API 前沿模型仍明显领先的三块。
  来源：https://arxiv.org/pdf/2506.04178 ；https://www.mindstudio.ai/blog/open-weight-vs-closed-frontier-models-agent-stack ；
  https://medium.com/@nairmilind3/llm-evaluation-in-2026-e631a78c67dc
- 中文社区结论一致：蒸馏能让 3B 在特定高难任务上超过 7B，但"复杂任务处理能力有限、可能继承偏见"
  是公认局限。来源：https://hub.baai.ac.cn/view/34185 ；https://blog.csdn.net/weixin_41688410/article/details/147180664

**对住小叮三类任务的映射：**

| 任务 | 任务型 | 蒸馏小模型可行性 |
|---|---|---|
| 评价回复 | 固定格式+风格生成，短上下文 | **高**——最典型的可蒸馏任务 |
| 质检（对话/服务记录打分抽取） | 分类+抽取 | **高**（但长记录受 CPU prefill 制约，见 Q3） |
| 调价建议 | 多因素多步推理+规划 | **低**——恰是小模型系统性弱项，出错即伤营收，不建议下放 |

### Q3. CPU 本地推理现状（无独显、16G 内存办公 PC）

- **生成速度（decode）**：2026-07 实测口径，现代办公 CPU（i7-12700 级）上 Q4 量化：
  Phi-4-mini 3.8B ≈ **12 tok/s**（占内存仅 2.3GB）、Gemma 4 E2B ≈ 15 tok/s、Llama 3.2 3B ≈ 10 tok/s；
  7B Q4 ≈ 5-12 tok/s。1.5-3B 档另有数据点：Qwen2-3B Q4 在 x86 4 线程下 22.7 tok/s。
  16GB 内存对 1.5-4B Q4（模型文件 1-3GB）绰绰有余，关键是权重必须整装入内存，否则速度崩塌。
  来源：https://www.promptquorum.com/local-llms/best-cpu-only-llm ；
  https://webscraft.org/blog/ollama-8-gb-vs-16-gb-ram-yaki-modeli-vidkrivayutsya-i-chi-varto-apgreyd-u-2026?lang=en ；
  https://huggingface.co/imi2/llama-2-7b-chat-pure-Q4_0-gguf
- **注意折扣**：上述基准多用 i7-12700 + DDR4/DDR5；酒店前台常见老旧 i3/i5 + DDR4 甚至 8G 内存，
  实际速度还要打折（内存带宽是主要瓶颈，DDR5-6000 比 DDR4-3200 快 15-25%）。
  来源：https://www.promptquorum.com/local-llms/best-cpu-only-llm
- **prefill（长提示）是硬伤**：llama.cpp 在纯 CPU 上提示处理时间近似随提示长度线性增长，
  社区结论"CPU 跑长上下文基本没戏（除非非常有耐心）"——几千 token 的质检记录或调价数据表，
  首 token 延迟会到几十秒级。批大小调优（512→2048）可提速 2-3 倍，但改变不了量级。
  来源：https://github.com/ggml-org/llama.cpp/discussions/229 ；
  https://github.com/ikawrakow/ik_llama.cpp/discussions/25
- **生态成熟度**：2026 年 llama.cpp（10 万+ star）/ollama 已是成熟基础设施——OpenAI 兼容 API、
  全架构支持、数千团队生产使用；llama.cpp 新增 Multi-Token Prediction、对 Qwen 架构专项提速 ~2.5x。
  但鉴权、配额、可观测性需自行拼装。
  来源：https://dev.to/sreeraj-sreenivasan/the-complete-guide-to-local-llm-inference-tools-in-july-2026-llamacpp-ollama-vllm-sglang-and-4mh1 ；
  https://startupfortune.com/llamacpp-adds-multi-token-prediction-and-doubles-qwen36-27b-throughput-for-local-inference/
- **可用性判决**：短提示（<1K tokens）+短输出（<300 tokens）的交互任务（评价回复、单条质检判定）
  在 3-4B Q4 下"可用但不惊艳"（一条回复 20-40 秒生成完）；批量夜间跑质检可行；
  长上下文交互任务不可用。基座候选：Qwen3 边缘系列（0.6B/1.7B/4B）表现超同级，
  Qwen3-4B 已"接近云端小型商用模型"。来源：https://arxiv.org/html/2505.09388v1

### Q4. API 价格趋势线：对比基线在怎么移动

- **DeepSeek 2026 剧情反转（重要）**：2026-05-23 宣布"永久降价"至原价 1/4——缓存命中输入
  0.025 元/M（"2.5 分钱"）、未命中 3 元/M、输出 6 元/M；但 **2026-08-13 宣布大幅涨价**（8-17 生效）：
  V4-Pro 峰时（9-12/14-18 点）输出 27 元/M（+350%）、缓存命中 0.3 元/M（+1100%）、未命中 9 元/M，
  谷时减半（13.5/0.15/4.5），最高涨 11 倍——"DeepSeek 不再白菜价"。
  来源：https://news.qq.com/rain/a/20260523A09LZ900 ；https://www.163.com/dy/article/L485A7RT05198NMR.html ；
  https://www.yicai.com/news/103317469.html ；https://m.jiemian.com/article/14884234.html
- **轻量档地板价仍在下探**：DeepSeek V4-Flash $0.14/$0.28（输入/输出每 M）；Qwen3.5-Flash 输入
  $0.030/M；豆包轻量模型低至 0.075 元/M 输入、豆包 1.5 Pro 输出 $0.30/M；Kimi K2.6 缓存命中地板
  $0.07/M。2026 上半年中国厂商共降价 6 次、3 次称永久。
  来源：https://dev.to/hassann/the-2026-chinese-llm-price-war-top-5-frontier-api-costs-compared-e1g ；
  https://www.llmabacus.com/en/chinese-llm-api-pricing
- **旗舰档在涨**：智谱 GLM-5 自 2026-02 起累计涨价约 83%（输出 $3.20/M，海外版涨 80-150%）；
  DeepSeek 旗舰同样转涨。Qwen3-Max 输入 $0.78/输出 $3.90 居中。
  来源：https://deepseek.csdn.net/6a41c122662f9a54cb8565fe.html ；
  https://www.uuaihub.com/blog/domestic-llm-api-pricing-2026
- **对基线的含义**：酒店任务量级下（每店每月 20-60 元），即使旗舰档全面涨 4 倍也只到 80-240 元/店/月，
  且可通过切换到轻量档/错峰调用对冲——轻量档价格战仍在继续。"自建省钱"的对比基线短期内不会
  向有利于自建的方向移动；但 2026 年旗舰涨价潮首次表明 **API 价格不是单向下行**，纯 API 依赖存在
  price-taker 风险，这是自建可选权（optionality）的价值而非现值。

### Q5. 维护税：基座季更下的重训节奏与小模型资产折旧

- **基座更新节奏**：Qwen 系 18 个月发 11+ 个旗舰版本（Qwen3 2025-04 → Qwen3.5 2026-02 →
  Qwen3.6 → Qwen3.8 2026-08），大致季更；但 2026 年 4-7 月 Qwen 出现 3 个月开源空窗，
  被解读为"旗舰转闭源、开源收缩"——**开源基座的持续可得性本身成为新风险**。
  来源：https://www.scriptbyai.com/qwen-timeline/ ；
  https://www.digitalapplied.com/blog/qwen-closed-flagship-pivot-open-weight-retreat-2026
- **重训节奏与折旧**：生产环境微调模型一般每 3-6 个月需要更新（数据漂移+更强基座发布）；
  大厂通常在下一代发布后 6-12 个月内弃用上一代，微调模型折旧更快；
  "当基座每 4-6 个月换代，维护微调版本就成了经常性开支"；不少组织的维护支出超过初次开发。
  来源：https://www.helicone.ai/blog/when-to-finetune ；https://www.solulab.com/ai-model-deprecation ；
  https://www.digitalapplied.com/blog/fine-tuning-llms-business-use-cases-guide ；
  https://blog.eduonix.com/2026/02/hidden-costs-of-fine-tuning-llms-for-production/
- **行业辩论现状（"微调死了吗"）**：2026 年共识是分叉——(1) 前沿模型+提示词+RAG 覆盖大多数场景，
  盲目微调是浪费；(2) 但"把前沿模型蒸馏进小开源模型、在高 token 量任务上把推理成本砍一个数量级"
  被认为是 2026 年微调最强的商业理由（"2026 is the year of fine-tuned small models"）——前提是
  **量要大**：例如每天 200 万次工单分类这种体量，20 倍单价差才决定项目生死。
  来源：https://seldo.com/posts/2026-is-the-year-of-fine-tuned-small-models/ ；
  https://hugobowne.substack.com/p/is-fine-tuning-dead-yet ；
  https://uditgoenka.co/p/small-language-model ；
  https://iterathon.tech/blog/small-language-models-enterprise-2026-cost-efficiency-guide
- **私有化 vs API 的国内主流建议**：预算 5-20 万的项目先用 API，业务验证成熟、调用量大后再评估
  私有化；本地部署成本至少含硬件摊提+电力+运维人力+机会成本四块。
  来源：https://www.jtti.cc/zh/supports/4275.html ；https://zhuanlan.zhihu.com/p/2038042303449847168
