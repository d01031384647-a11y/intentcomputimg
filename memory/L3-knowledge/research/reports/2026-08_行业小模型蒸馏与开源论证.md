# 行业小模型蒸馏与开源：论证与判决

**日期**：2026-08-13 ｜ **议题**：是否让李冀把开源大模型蒸馏为酒店行业小模型并开源（动机：最低成本调用 + 开源赢得市场认可）
**证据**：两路全网研究共 48 次检索（raw/34 垂直自研开源先例、raw/35 蒸馏成本与效果现状），所有事实附来源

---

## 〇、判决

**现在不做。两个动机在证据面前都不成立；但保留一个写死触发条件的"期权"，并给"赢得认可"换一个便宜一百倍的实现方式。**

## 一、动机①"最低成本调用"：账算不平，差两个数量级

- **现状基线**：DeepSeek 等 API 下，每店每月推理成本 20–60 元，占 ARPU 的 1–2%——**要省的东西本身就小**
- **蒸馏的真实全口径成本**（raw/35，2026 年行情）：单次训练算力+数据合成确实便宜（1000–5000 元），但全口径（数据工程占 40–60%、3–5 轮迭代、每周期评测 $500–2000）为 **5–30 万元**；且基座季度级更新（Qwen 18 个月发 11+ 版），微调模型每 3–6 个月需重训——**年化维护 15–40 万元，人力是大头，TCO 普遍被低估 3–5 倍**
- **打平点**：按省下 API 全额计算，需要 **约 300–1600 家活跃门店**才回本——我们 10 月的目标是 3–5 家付费店，差两个数量级
- **李冀的机会成本是最贵的一项**：他 3–6 个月的投入（25–50 万薪酬口径）押在采纳率≥25% 这条 M1 生死线上，每一天挪去训模型都是从公司唯一壁垒上抽血
- 新变量诚实披露：API 价格不再单向下降（DeepSeek 2026-08-17 起部分档最高涨 11 倍、GLM-5 累涨 83%，但轻量档地板仍在下探至 $0.03/M）——**这给蒸馏留了一个"对冲涨价"的期权价值，但期权不等于现在行权**

## 二、动机②"开源赢得市场认可"：零个已核实案例，且自相矛盾

1. **先例判决**（raw/34）：
   - **BloombergGPT 是反面教材之首**——5000 万美元级金融专训模型，发布后被无金融专训的 GPT-4 在几乎所有金融任务上少样本击败，此后无二代、不开源、退为内部工具
   - **成功自研者全是规模化之后 + 全部闭源**：Intercom Fin（约 1 亿美元 ARR 后才发 Fin Apex）、Harvey（80 亿美元估值后基于 Kimi 后训练）、Cursor（5 亿美元 ARR 后自研 Composer）——**无一开源、无一发生在早期**；Sierra（158 亿美元估值）至今用前沿 API+微调层
   - **"开源垂直模型换商业回报"：零个已核实案例**——开源垂直模型的发布方是巨头（Google MedGemma）或高校（北大 ChatLaw）；企业生产负载中开源 LLM 份额仅 11% 且同比在降
   - 放弃者名单很长：Aleph Alpha、Adept、Character.AI、零一万物、百川……Foundation Capital 的总结："自研模型是能力税，不是护城河"；朱啸虎（2025）："创业公司不要浪费一分钱训练底层模型"
2. **受众错位**：酒店老板按 RevPAR 结果买单，不看 Hugging Face；投资人 2026 年的共识是"护城河=专有数据+工作流+分发"，6 人团队宣称自研模型在尽调里更可能被读作**烧钱信号**而非技术实力
3. **自相矛盾（最致命）**：我们的护城河=定价 know-how+"建议→采纳→结果"数据闭环。蒸馏行业模型必然要用这些数据做训练语料——**再开源，等于把护城河印成传单发给每一个同行**。DeepSeek-R1 之后企业自己蒸馏门槛极低，没有人需要买（或感谢）一家创业公司的行业小模型
4. 参照：携程"问道"声量式微，其对客产品 TripGenie 实际跑在 Azure OpenAI 上——**连携程都不坚持自研叙事了**

## 三、任务分层：哪些"小模型"永远可以做（但那不叫行业大模型）

| 任务类型 | 小模型可行性 | 我们的对应场景 | 处置 |
|---|---|---|---|
| 分类/抽取/固定格式生成 | ✅ 3.8B 级已可打平 GPT-4o（结构化抽取） | OTA 页面结构化、评价情感分类、质检报告格式化 | 需要时用现成开源小模型+少量微调，**几天的活，不是战略项目** |
| 视觉窄任务 | ✅ 标准 CV 微调 | 保洁验收模型（本就在改造计划内） | 照计划做，与"行业大模型"无关 |
| **多步推理/长上下文规划** | ❌ 差距未收窄 | **调价建议——恰恰是公司的命** | **永远用当下最强的模型**，一分钱不省 |
| CPU 本地推理 | ⚠️ 3–4B Q4 在 16G 无显卡 PC 上 10–15 tok/s，短任务可用；长上下文不可用；酒店老旧机器再打折 | 桌面端离线兜底 | 期权，不建仓 |

## 四、期权条款（写死，避免反复讨论）

**重启此议题当且仅当满足以下任一条件**：
1. 活跃门店 ≥300 家（省钱账开始成立）
2. API 年支出 ≥50 万元，或单店月推理成本因涨价突破 200 元（对冲价值成立）
3. 完成 A 轮且组建专职模型团队，需要"专有数据后训练"叙事（Fin/Harvey/Cursor 剧本的入场券——注意他们全部闭源）
- 期权维护成本：**每季度半天**，李冀出一页《基座与成本水位评审》（基座更新、API 价格、本地推理进展）——这是他"训模型肌肉"的正确用法，也让这个话题有固定出口，不再随机打断主线

## 五、"赢得市场认可"的便宜替代品（成本约为蒸馏开源的 1/100）

1. **开源 HotelBench 行业评测集**（而非模型）：一套"酒店经营 AI 任务"公开评测（调价场景题/评价理解/工单调度），几周工作量、不泄露任何 know-how——**谁定义评测，谁定义行业标准**；所有大模型厂商跑分时都在替我们传播
2. 实测报告与技术博客（已在营销计划内）：《你的酒店能被 AI 卖出去吗》系列
3. 若坚持要开源代码资产：开源桌面端的**通用组件**（如卡片渲染框架），绝不开源 OTA 适配器与算法层

## 六、给李冀的沟通方式（保护积极性）

他有预训练/SFT/RL 的完整肌肉，对训模型有天然冲动——不要说"不做"，说"**现在的杠杆在数据侧，模型侧留了写死的触发器**"：①质量仪表与误差归因体系是"未来后训练语料"的生产线（Fin/Harvey 的入场券正是专有交互数据——他现在做的每一天都在为将来可能的自研攒弹药）；②季度模型评审由他主笔（保持手感）；③HotelBench 评测集由他设计（技术声望的正确出口）。

## 七、一句话总结

**"用别人的模型、攒自己的数据"是 2026 年被 Fin、Harvey、Cursor 用几十亿美元验证过的唯一顺序——先有一亿 ARR 和专有数据，再谈自己的模型，而且到那天也应该闭源。现在蒸馏开源，省不到钱、赢不到客、还把护城河送人。**
