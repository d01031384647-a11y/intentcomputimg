# 深圳硬件供应商行前方案（呈董事长）

**日期**：2026-08-12 ｜ **用途**：董事长深圳行的拜访名单、提问卡与砍价锚点
**调研方法**：五路并行全网搜寻（约 60 次检索），完整材料见研究仓库 raw/29–33。联系方式均为公开渠道线索，未经电话核实的已标注。
**采购定位（先统一认知）**：POC 两家店的量——按钮几十个、公共区摄像头每店 2–4 路、自助机 1–2 台，45 店满配也仅几万元级。**我们找的是方案商/成品商/公版 OEM，不是开模的工厂**；谁上来谈模具和 NRE，礼貌结束。

---

## 一、技术选型结论（先定路线再见人，否则聊不到点上）

1. **按钮：Zigbee 3.0 成品按钮 + 自建网关**（店内桌面主机插 USB 协调器跑开源 zigbee2mqtt）——单击/双击/长按三动作以标准语义直达我们的桌面引擎，**零云依赖、零 API 年费**。排除：WiFi（费电）、433 服务铃（单向无确认、生态封闭）；LoRa 留作二期全店员工 SOS。电池 CR2032 实际 12–24 个月，换电写进保洁 SOP。
2. **摄像头：标准 ONVIF/RTSP 相机（100–300 元/路）+ 店内本地分析**——POC 直接用店内电脑跑模型（零增量硬件），满配再上边缘盒（RK3588 约 2499 元管 8 路）。**视频不出店、只上报结构化事件**——这既是隐私合规姿势，也省掉所有云 API 年费。"异常滞留/物品遗留"用海康/大华普通款内置智能事件即可零成本解决；只有"保洁验收"需要自训模型。
3. **自助机：读证核验为主、扫码电子登记兜底、不留人脸库**（2025 年新规后的正确姿势）——**硬门槛是北京公安旅业系统对接**，深圳设备到北京用不了就白买，每家必索"北京可回访的在营酒店案例"。

## 三、随身红线卡（三句话）

1. **客房内不装任何摄像头；人脸不做方案核心**——2025 年《公共安全视频管理条例》+《人脸识别技术应用安全管理规定》双规，谁主推人脸方案直接换话题
2. **量小不谈开模**——POC 几十件、满配几万元级，只买成品/公版/贴牌
3. **封闭生态一票否决**——每家必问一句："不经你们的云，本地局域网（MQTT/HTTP/RTSP）能不能完整使用？"答"不能"的，记录后离开
