# 李冀与杨敬港的角色定义（1.0 交付后）

**日期**：2026-08-12 ｜ **背景**：股东对 1.0 交付后两位大模型工程师的工作安排"没有头绪"
**第一性诊断**：没头绪的根源是"功能清单"思维——功能有做完的一天。公司真正的产出是两个永不停转的飞轮，AI 工程师应各自拥有一个飞轮，工作由指标自动生成，而非由任务清单驱动。

## 公司的两个飞轮

```
【决策质量飞轮】数据 → 建议 → 采纳/忽略 → 结果 → 误差归因 → 更准的建议
  （公司唯一的壁垒。采纳率与RevPAR提升由它决定，收费依据由它产生）
【数据与连接飞轮】更多店接入 → 更多数据源变体 → 更稳的采集 → 更完整的数据
  （护城河的物理载体。OTA后台一改版全国客户同时坏——这条"永久税"必须有人专职扛）
```

## 李冀 = 决策质量飞轮 Owner（对内称"收益算法负责人"）

**为什么是他**：14 年算法+对话式 BI（智能问数+智能归因）经验，全公司只有他配得上"公司唯一壁垒"这个位置；他的薪酬只有放在这里才值回来。

**周节奏（常态化，不再按项目排）**：
- 周一：**误差归因会**（30 分钟，敬港同席）——上周每条建议 vs 实际结果，逐条分诊：算法错？数据错？店家没执行？
- 周中：规则/系数迭代（定价规则手册的持续编码化、两个调价系数、事件系数的扩充）
- 周五：发版 + 下周策略预置（节假日/演唱会/展会事件日历）

**长期工件**：①质量仪表（每条建议的置信度与事后验证——按结果计费的对账地基，也是防"确认沦为橡皮图章"的机关）；②竞争圈定义算法（每店 5–8 家竞对的选法本身就是 know-how）；③bot 对话追问("为什么这么建议")——他的对话式 BI 经验直接复用；④黄金周策略包（10 月大考）。

**KPI**：建议采纳率（锚 25%→40%）、市场校正 RevPAR 提升、建议误差率。**M1 门径里"采纳率≥25%"就是他的目标线。**

**两条红线任务**：算法设计文档每周入库（单点风险对冲，制度而非自觉）；敬港为其影子位。

## 杨敬港 = 数据与连接飞轮 Owner（对内称"数据管道与集成负责人"）

**为什么是他**：OCR/VLM/RAG/管道化的应用落地经验，正匹配"从各种界面把数据稳定拿回来"这件事。

**职责清单（按优先级）**：
1. **采集稳定性值班制**：OTA 后台/竞对页面改版的监控告警+修复 SLA（24h 内），这个脏活就是护城河本身
2. 新店接入的 PMS/OTA 变体适配（目标：单店接入时长持续下降，适配模板库持续增厚）
3. 埋点完整率（建议→推送→采纳→结果链路无缺口——李冀的原料，公司的资产）
4. OpenClaw/微信推送通道维护；9 月代管工作台后端；10 月按钮网关事件接入（POC 硬件回来后）
5. 二期：多 AI 入口 SKILL 封装（微信 AI/千问，规则明朗后）

**KPI**：数据完整率（≥99%）、采集故障恢复时长、单店接入耗时、适配库数量。**"9 月 10 家店部署顺畅"就是他的目标线。**

## 两人的接口与管理机制

- **接口就一个**：李冀消费数据，敬港保障数据；周一误差归因会当场分诊，不留扯皮空间
- **你只需要管一个会**：每周 30 分钟"质量复盘会"（你或冬梅主持），看三个数——采纳率、误差率、数据完整率。数不达标，工作自动生成；达标了，两人自己知道往哪深挖。**你管指标，不管任务。**
- **禁止清单**（防跑偏）：不做新数字员工（一个能收费的员工>五个演示用的）、不碰通用能力、不追新模型热点——研究判决早已明确：技术不是瓶颈，质量和数据才是
- 两人各留 20% 时间轮值试点店支持（全员听得见炮火）
