# 微信 AI 生态接入准备方案（基于公开信息，2026-07-24）

> 依据：raw/07（微信智能体与小程序生态）、raw/20（微信触达与推送规则）、raw/23（进展增补至 07-24）。
> 股东决策（2026-07-24）：微信方案先按外界公开描述制定，不等内部渠道信息。
> 定位衔接：本方案即「第一收入曲线：微信 AI 接入改造服务」的产品原型——先在住小叮跑通，再 SOP 化对外收费。

## 一、形势判断（截至 2026-07-24）

| 事项 | 状态 |
|------|------|
| 微信 AI 助手"小微" | 灰度中（自媒体估算约百万级用户），8.0.76 持续扩大；Q3 全量为媒体披露目标，取决于监管审批 |
| 开发者接入 | 《开发者接入微信AI生态指引》2026-06-08 发布：自动模式（零开发，授权微信读小程序代操作）/ 开发模式（mcp.json 把功能封装成 SKILL，需审核） |
| 中小商家通道 | 名义上 6-08 起全开放、无批次限制；但截至 07-24 **零例中小商家被小微实际调用的公开案例** |
| 交易闭环 | 实测"差最后一步"：可达下单确认页，支付需用户逐笔确认（AI 专属卡机制）；**酒店链路实测卡在授权页** |
| 排序/抽佣/竞价规则 | **零披露**——第三方分发机会不可量化，这是最大外生变量 |
| 激励 | 7-07 成长计划加码：Token 补贴 1亿→10亿、虚拟支付限时优惠费率、广告免开发接入 |
| 合规 | 7-15 智能体新规仅打击拟人化情感陪伴类；任务型数字员工安全，**勿做人格化人设** |
| 竞争格局 | 首批内测为美团/携程/同程/滴滴/京东等巨头；腾讯持同程 20.46%，酒旅泛需求默认履约方大概率是同程 |

**结论：现在动手的价值不在马上拿到流量（泛需求轮不到单体酒店），而在①抢"指名调用+属地长尾"；②把接入 SOP 打磨成可售卖的服务；③用实测数据做销售弹药（"小微订酒店会卡在授权页——我们帮你修好"）。**

## 二、目标（按优先级）

1. **住小叮小程序被小微成功调用完成一次真实订房**（指名调用），全程录屏——这是公司最重要的一条销售素材
2. 沉淀《单体酒店微信 AI 接入 SOP》：改造清单、mcp.json 模板、审核要点、实测脚本
3. 形成可售卖的服务包：一次性改造 1000–3000 元 + 年维护 500–1000 元（定价依据 raw/18）

## 三、技术路径：双轨并行

### 轨道 A：自动模式（本周可做，零开发）
- 按指引完成小程序"自愿接入 AI 生态"的声明/授权，让微信 AI 可读取并代操作
- **前提是小程序本身"智能体友好"**——实测显示弹窗多、流程绕的小程序会让小微卡死。改造清单：
  1. 订房主流程 ≤3 步：选日期/房型 → 确认 → 支付，砍掉开屏弹窗、强制登录前置、营销浮层
  2. 全部用微信标准组件（自定义炫酷控件是 AI 的地雷）；按钮/字段语义命名清晰
  3. 房态房价实时准确（云房态）——AI 渠道订到无房是信任事故（raw/13：超售是行业日常）
  4. 支付走酒店自有微信商户号（合规：消费者直付，平台不碰资金）
- 完成后立即开始实测（见五）

### 轨道 B：开发模式（2–4 周，深度接入）
- 用 mcp.json 把核心能力封装成 SKILL：`查房态(日期,人数)`、`报价(房型,日期)`、`下单(房型,日期,联系人)`、`查订单/取消`
- 提交微信审核；记录审核每一步的要求与耗时（这些是 SOP 的核心内容，也是服务收费的依据）
- 对齐 AI 专属卡/支付确认机制，确保"AI 建议 → 用户一键确认支付"闭环
- 命名与人设：功能型描述（"住小叮订房助手"），**不做拟人化陪聊人设**（7·15 新规）

## 四、B 端触达（卡片体系的通道落地，依据 raw/20）

- 老板侧每日经营卡片走：**一次性订阅消息"授权飞轮"**（老板每次点确认/忽略时弹 3 模板勾选"总是保持以上选择"静默续权）+ **服务号模板消息**（别样红每日经营推送多年被默许的先例）
- 兜底：企业微信人机协同 1v1 + 通知类短信（0.036–0.05 元/条，不带链接）
- **红线：绝不做个人微信自动化**（WeTool 封杀先例）；文案绝不营销化
- 频次纪律：每日 1 张聚合卡 + 高价值事件卡，每周高价值卡 ≤3 张

## 五、实测清单（每周执行一次，留存记录）

1. 指名调用："帮我订住小叮 XX 店明晚一间大床房" → 能否唤起、走到哪一步、卡点截图
2. 泛需求露出："帮我在 XX 附近订个 200 左右的酒店" → 住小叮是否出现、排在谁后面（大概率是同程/美团，记录下来）
3. 交易闭环：走到支付确认页的成功率、AI 专属卡体验
4. 卡点归档：每个失败点 → 改造项 → 复测结果（这份记录=服务产品的知识库）
5. 同步监测：竞对（同程/美团小程序）在小微中的表现作为基准

## 六、时间表

| 时间 | 动作 |
|------|------|
| 即刻–8月初 | 住小叮小程序智能体友好改造 + 自动模式接入 + 首轮实测 |
| 8月中 | 盯腾讯 Q2 财报电话会（微信 AI 商业化口径、全量时间表）；开发模式 SKILL 提审 |
| Q3 全量后 2 周内 | 完整实测报告 → 转化为销售案例与服务包定价确认 |
| 持续 | 每周复测；跟踪排序/抽佣规则披露（一旦公布立即重估第三方机会大小） |

## 七、风险与止损

- **排序规则风险**：若全量后泛需求全部导给同程/美团且指名调用体验差 → 接入服务的卖点降级为"防御性标配"，定价下调，重心转向调价数字员工
- **中小商家实际不被调用**：若 Q3 后 4–8 周仍零案例 → 将实测证据公开化（内容营销），同时把接入服务扩展到千问/支付宝/抖音等多 AI 入口（"全渠道 agent-ready"），不吊死在微信
- **投入止损线**：本方案总投入控制在 1–2 人月内；在规则明朗前不做任何按流量付费的投放
